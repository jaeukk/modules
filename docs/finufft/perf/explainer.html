Multi-component optimization on FINUFFT

The ground-state search for multi-component stealthy packings spends almost all of its time inside one function call: the energy and forces of every species' collective coordinates. This page shows what changed in that calculation and why each change pays off: four changes (A to D) in a first round, then four follow-ups (E to H) found by measuring what remained.

One evaluation, before and after

L-BFGS calls the potential a few thousand times per configuration. Each call rebuilds the bookkeeping, computes the energy, then the forces. Four independent changes, labeled A to D below, each remove a different cost. The prepare step makes every FINUFFT plan before any parallel region starts, so the parallel parts only execute.

What each evaluation computes

Each species s has its own particles and its own set of constrained wavevectors \mathcal K_s, all reciprocal-lattice vectors with 0 < |\mathbf k| \le K_s in one half-space. The collective density and the potential are

\rho_s(\mathbf k)=\sum_{j\in s} e^{\,i\mathbf k\cdot\mathbf r_j},\qquad \Phi=u_0\sum_s \frac{N_s}{N}\,\frac{1}{V}\sum_{\mathbf k\in\mathcal K_s}\tilde v(\mathbf k)\,\bigl|\rho_s(\mathbf k)\bigr|^2+e_0\,\Phi_{\mathrm{contact}}

and the collective-coordinate force on particle j of species s is

\mathbf F_j=\frac{2u_0N_s}{NV}\;\operatorname{Im}\sum_{\mathbf k\in\mathcal K_s}\tilde v(\mathbf k)\,\mathbf k\,\overline{\rho_s(\mathbf k)}\,e^{\,i\mathbf k\cdot\mathbf r_j}\;+\;\mathbf F_j^{\mathrm{contact}}.

Done directly, the densities cost O(N_sM_s) sines and cosines per species and the forces another O(N_sM_s) with d components each, where M_s=|\mathcal K_s| grows like \chi_s\,d\,N_s. At χₛ = 0.4 that is 320 modes for each of 2000 particles, twice per evaluation.

The constraints already sit on an FFT grid

In a periodic cell with basis \mathbf a_d and reciprocal basis \mathbf b_d, every constraint is an integer combination of the reciprocal basis. With fractional coordinates \mathbf s_j the phase becomes a dot product of integers with angles, for any cell shape, skewed ones included:

\mathbf k=\sum_d n_d\,\mathbf b_d,\quad n_d\in\mathbb Z\qquad\Longrightarrow\qquad \mathbf k\cdot\mathbf r_j=\sum_d n_d\,(2\pi s_{jd}).

So \rho_s is a non-uniform FFT of Type 1 (particles to Fourier modes) evaluated on the integer mode grid, and the force sum is a Type 2 transform (Fourier modes back to the particles). FINUFFT spreads each particle onto w^d points of an oversampled grid, runs one FFT, and corrects for the kernel:

\text{direct: } O(N_sM_s)\qquad\longrightarrow\qquad \text{NUFFT: } O\!\left(N_s\,w^d+G\log G\right),\quad G=\prod_d(2K_d+1).

Using the NUFFT for collective-coordinate optimization was motivated by A. Shih, M. Casiulis and S. Martiniani, Fast generation of spectrally shaped disorder, Phys. Rev. E 110, 034122 (2024), which reaches O(N log N) cost this way and generates stealthy hyperuniform configurations of up to 10⁹ points.

A fix that came first. Before any of this could pay off, FINUFFT had to be used at all. The existing code decided whether a constraint is a lattice mode with a rounding test so strict that, at ε = 10⁻¹², it rejected every mode with an index above about 43/d. In 1D, and in 2D or 3D at large N, it silently fell back to direct sums. Modes whose index is integral to machine precision are now accepted; genuinely off-lattice vectors still fall back.

AForces as a Type 2 transform

Before, every particle looped over all M_s modes of its species: the largest single cost once the densities used FINUFFT (4.6 ms of 6.4 ms at χₛ = 0.4). Now each species places c_a(\mathbf n)=\tilde v(\mathbf k)\,k_a\,\overline{\rho_s(\mathbf k)} on its constrained modes and runs one batched Type 2 transform with sign +1; the imaginary part times 2/V is the force, which is then scaled by u_0N_s/N.

A transform has a fixed cost that the direct loop does not, so tiny systems would get slower. A deterministic cost gate decides per species from the problem size and the thread count only, never from timing, so two runs with the same settings take the same path:

t_{\mathrm{direct}}=\frac{P_d\,N_sM_s}{T},\qquad t_{\mathrm{Type\,2}}=C_d+Q_d\Bigl(\tfrac{w}{13}\Bigr)^{d}N_s+R_d\,G,\qquad \text{use Type 2 if } t_{\mathrm{direct}}\ge 1.3\,t_{\mathrm{Type\,2}}.

When several species run concurrently (option C), the rule is applied jointly: their Type 2 costs overlap across threads, so species that would not pay alone can still be accepted together. The constants were fitted on the development machine (Ryzen 5 7500F, FINUFFT 2.5.1) and are refit with the tools in apps/CCOptimization/tests/finufft_gate/ on another node.

BPlans built once

FINUFFT's simple interface builds a plan, uses it once, and destroys it. For a 400-particle species on a 21 × 21 mode grid, building and destroying cost far more than the transform itself:

Each species now keeps its plans (Type 1 for densities, Type 2 for forces) and its constraint-to-mode map between evaluations. Before every use the inputs are compared bit for bit with those the plans were built from: dimension, particle count, tolerance, thread setting, mode cap, cell vectors and every constraint vector. Any difference rebuilds; moving particles only calls setpts. Copies of a potential start with an empty cache, so a plan is never shared or destroyed twice.

CSpecies in parallel

Repeatability rules out letting FINUFFT split one transform across threads: its spreading then sums in an order that changes from run to run. Before, each species' transform therefore ran on one thread while the others waited, and every species opened its own small parallel region. Now one parallel region hands whole species to threads; a thread that finishes early starts on the contact sum.

Every species is computed start to finish by one thread with fixed arithmetic, and its result goes to its own slot; slots are added in species order afterwards. The bits therefore do not depend on which thread ran which species. A species that cannot use FINUFFT (an unusual cell, say) keeps the old path with all threads.

DIndex views instead of copies

Each species' potential used to receive its own copy of its particles, rebuilt on every evaluation. It now reads the one full configuration through a list of particle indices, in the same order as before, so the arithmetic, and the bits, are unchanged.

EOne neighbor walk for energy and forces

The optimizer always asks for the energy and the forces of the same configuration. The contact part used to walk every particle's neighbor list twice, once per request. A combined call now walks it once, filling the particle's energy slot and its contact force together, and lets the species' transforms overlap that walk instead of running in a phase of their own. The results are bit-identical to the two separate calls, and full optimizations end at the same coordinates.

The combined call is a separate interface that MultiStealthyPotential implements and the optimizer looks up at run time. Adding it as a new virtual function of the potential base class instead, as a first version did, crashed applications built against the old object layout; the Codex audit caught that.

FA shorter L-BFGS history

Timing a whole optimization showed L-BFGS's own bookkeeping at 24–38% of the run once the potential was fast: with 100 stored correction pairs it costs more per step than the energy and forces it consumes. The history is now a setting, history N in the ground block (default 100, unchanged).

GContact cells sized to the cutoff

The question was whether threads sat idle while species ran. They hardly did (1–4%), but the measurement showed something else: at N = 10 000 the contact sum took 80% of an evaluation and grew as N^2. Random packings start from a unit box with 10 cells per side; rescaling to the real box size keeps those 10 cells, so in 2D each one holds about 1% of all particles, and every contact query checks nine of them.

Both drivers now size the cells to \max\bigl(r_c,\,(V/N)^{1/d}\bigr): one cutoff, but never much fewer particles than cells. The multi-component potential re-bins its own copy of the configuration. The one-component driver sets the size once on each starting configuration, and the optimizer's per-step copies inherit it, so no step pays for re-binning (doing it inside that potential would have cost a copy per step, 15–20% at N = 500).

HSpecies work in particle blocks

With the contact sum cheap, one species per thread does leave threads idle when there are fewer species than threads, as in binary mixtures. Each species' transforms now run as contiguous particle blocks, each with its own persistent plan, and the blocks are spread over the threads; threads without transform work take contact chunks.

The two transform types split differently. FINUFFT interpolates every particle independently from the same fine grid, so Type 2 forces are bit-identical for any block count, and the gate may choose that count from the team size. Type 1 densities are sums over particles, so their block count depends only on the problem size and tolerance, never on the thread count; the blocks' modes are added in block order. At χₛ = 0.4 every benchmarked species keeps one Type 1 block, so those results are bit-identical to before.

What stays fixed

  • Direct sums remain the default. With the Direct backend, the collective-coordinate energies and forces are bit-identical to the September code in 1D to 3D at 1, 4 and 8 threads; contact sums follow the new cell order (G).
  • Repeating a run with the same build, settings, thread count and input gives bit-identical results.
  • FINUFFT and direct sums agree to better than 10⁻¹³ relative in energy and forces. Their optimization endpoints can differ, as before, because L-BFGS amplifies rounding-level differences.
  • Endpoints are not bit-identical to builds before October 14 (G, and H for species split into several Type 1 blocks); they remain valid ground states.
  • The optimizer and its three-pass schedule are untouched; only its history length became a setting (F).

To use it: build with make -C apps/CCOptimization USE_FINUFFT=1 and add the keyword finufft to the ground or MD block before run, in the multi-component driver and in the one-component driver alike; history 40 in the multi-component ground block shortens the L-BFGS history. A one-component 2D ground state with N = 2000 took 14.4 s with direct sums and 0.8 s with finufft.
